# 0.5 "Full Rules Ahead" — where it stands

Written at commit `b0556c5`, 23 commits ahead of `origin/develop`. Read this
before continuing 0.5; it records what was decided and why, which the diff
cannot. Everything here was measured against `AnomalyHuntersCampaign/`, not
recalled.

## The theme, and the measurement behind it

0.5 began as "AI quality" and became "move the rules into the app", because of
one number: of the campaign's sheets that state a point total, **none added up
to its own brackets**, and the median error was 34%. Abella, a 100-point NPC,
was 34 points over.

That is not a prompt that needs tightening. **The cost of a line is not a
property of the line.** `Guns (Rifle)` is priced partly by whether
`Guns (Pistol)` is on the same sheet (B171, B175); a disadvantage by its
self-control number (B123); a skill by a difficulty printed in the book and not
on the sheet. A model writing prose cannot hold that graph, and the schema was
asking it to — `CharacterData`'s own field descriptions gave
`"Combat Reflexes [15]"` and `"Brawling (DX+1)-13 [2]"` as the shape to produce.

So: **the model chooses, the app prices.**

## Decisions that are not in the code

These were settled with the GM and should not be relitigated without them.

- **Advisory only.** The app reports; it never corrects and never blocks. Where
  the rules are silent, so is the app. A finding is a sentence, not a refusal.
- **A declared price is the answer.** A trait in `System_Rules.json`
  → `customTraits` is priced at the GM's figure, not the book's. It is their
  table. Two are declared: Combat Paralysis at -5 and Struggling at -5.
- **Strings stay as stored.** The campaign's `"Name (Base)-Level [Points]"`
  format is unchanged. The structured work renders *into* it. No migration, and
  the renderer written for the AI path is the first half of one if it is ever
  wanted.
- **The big prompt stays for now.** Reducing it waits until the catalogue is
  demonstrably complete.
- **Catalogue from GURPS 4e, Basic Set first.** Then the books the campaign
  lists: High-Tech, Martial Arts. `rules_db/*.sqlite` is gitignored and built
  from the GM's own PDFs; nothing of the book ships in this repo.
- **Campaign data is the GM's.** It is gitignored. Fix it with them, never
  behind them, and compare against a backup afterwards rather than grepping for
  the string you expected to change.
- **Most users are on free tiers of hosted models.** Output size and
  reliability matter more than elegance.

## What exists now

**The catalogue** — 809 entries read from the Basic Set's own Trait Lists
(pp.299-306): 259 advantages, 227 disadvantages, 267 skills, 56 modifiers, with
each one's printed cost, page and difficulty. 8 rows are flagged for review.

**The rules** (`web/src/lib/`) — every figure cited to a page:

| file | what it holds |
|---|---|
| `gurpsRules.ts` | attribute and skill costs, derived figures, self-control (B123) |
| `pointBuild.ts` | reads a sheet's own strings into arithmetic |
| `traitResolver.ts` | matches a sheet's trait to the book's entry |
| `traitAudit.ts` | catalogued / declared / nobody-prices-it |
| `modifiers.ts` | enhancements and limitations (B103) |
| `mechanicsCheck.ts` | the checker: findings, label findings, and declines |
| `characterBuild.ts` | prices a chosen build and writes the stored line |
| `noteMarkup.ts`, `entityKind.ts` | note markup, and what an entity is |

**The AI contract** — `src/gurpsai/domain/character_build.py`. A `CharacterBuild`
has nowhere to put a cost, which is worth more than any instruction telling a
model not to give one. It has an `unpriceable` list for what the book does not
price with a figure. The Marauder persona no longer says "always show point
costs"; `create_npc.md` says choose rather than calculate.

**The editors** — advantages and disadvantages are picked from the catalogue and
priced by the app. A saved cost is never rewritten without the GM pressing
something. `@` in a note links an entity by name.

## What is deliberately not finished

1. **The generation path is wired, and not yet run against a live model.**
   `create_npc` asks for `build` (`CHARACTER_BUILD_SCHEMA` in `wizards.ts`, an
   inlined copy of `CharacterBuild` because Gemini takes no `$ref` and no
   integer enum; field names pinned in both test suites). The router keeps
   `build` past `CharacterData` validation; `generatedSheet.ts` prices it.
   Settled with the GM: an unpriceable choice stays on the sheet bracketless
   with its reason; the model's `unpriceable` list is appended to `gmSummary`
   under "Left to the GM". Still to do: one real generation, and measure how
   many of a model's names the catalogue actually resolves.
2. **90 dead references.** Of 93 file paths written into campaign prose, 90
   point at `.md` files the migration to JSON replaced — mostly relative
   (`./Locations/HQ.md`). Jamie's and Povo's were rewritten as `[[Name]]`
   references by hand. The rest want a repair pass, reviewed before it writes.
3. ~~Two trait parsers disagree.~~ **Resolved.** The sheet view reads
   attributes, traits and skills with `pointBuild.parseEntry`, and
   `parseTrait`/`TraitEditorList` were dead and are deleted. AI Mend (the
   repair prompt) was removed by decision: files are correct when written.
   Still open: 15 skill lines in the six bestiary sheets (the Lizards,
   Vulture) are corrupted from the markdown migration —
   `B ()- [0] - rawling (DX/E)-16 [[4]]` — present in both backups. The GM's
   to fix in their one-off pass.
4. **Languages are uncatalogued.** They are priced by comprehension level
   (B23-26) and are not in the Trait Lists, and the comprehension table did not
   survive extraction. Povo has two languages at Native/Native both costing 0,
   and B25 is explicit that only one native tongue is free. Every character with
   a second language hits this.
5. **Coverage.** 63% of lines are priced. Recognising the derived attributes
   (Dodge, Parry, Block — 58 lines, never bought) and growing the catalogue past
   meta-traits and varieties reaches roughly 84%; mining the variants the book
   enumerates in entry prose (B129 gives Cold-Blooded as -5 below 50 degrees and
   -10 below 65) reaches about 89%. The rest is a short list of real decisions.
6. **Queued from 0.4 and untouched.** Entity-type indicators when two things
   share a name; PCs always visible under focus; the focus rework; `region`
   beside *Inside*; modernising `sync_pc_from_gcs.py`.
7. **Not released.** `web/package.json` still says 0.4.0 and nothing is tagged.
   The changelog's 0.5.0 section is written.

## Things that will bite you

- **Shared matching rules.** `link_resolver.py` ↔ `entityResolution.ts` and
  `naming.py` ↔ `naming.ts` are deliberately mirrored and carry comments saying
  so. Do not add a third. `TraitNote` resolves names through `entityResolution`
  for this reason.
- **Tests that pass against the bug.** Two editor bugs were caught only after
  the first test passed. A list editor is controlled, so a `vi.fn()` parent
  never feeds the value back; and typing must be built from what the field is
  *showing*, not from the string you meant to type. Both failures looked like
  green tests.
- **`[0]` is a real cost.** A native language and a native culture are free
  (B23-24), and `Doesn't Breathe (Gills)` is a nought-point feature (B51). Never
  treat a zero as unfinished.
- **The campaign's own files are the best test data.** The wrong skill page
  range, the missing levelled-trait alias, two false modifier findings and the
  whole Talent-class false positive were all found by measuring, not by reading.
- **The Vite watcher misses edits on this machine.** Twice the dev server kept
  serving an old module after a change, and a page reload did not help.
  `curl localhost:5173/src/lib/<file>.ts` shows what is actually served;
  restart the server before trusting a live check.
- **CI runs `python -m pytest tests/` only.** Tests must live in `tests/` and
  must not need the gitignored rules database.
